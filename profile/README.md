# UIC CCS Mobile Development (2026-2027)

Welcome to the official GitHub Organization for **CC020.23 — Mobile Applications Development** under the College of Computer Studies. This organization hosts all student final project repositories, enforcing industry-standard version control, agile project management, and collaborative development practices.

## 🛡️ The AI "Code Defense" Standard
This course operates under a strict engineering mandate established by Prof. Joshua M. Cister: **"AI as your assistant, your brain as the engineer."** 

While generative tools can assist in scaffolding and debugging, passing compilation alone does not guarantee a passing grade. For your final submission, you must complete a live oral code defense and a video walkthrough justifying your software architecture and logic line-by-line. 

## 📂 Repository Setup & Privacy Instructions
To maintain academic integrity and simulate a closed-source enterprise environment, all teams must adhere to the following setup rules:

1. **Create a Private Repository:** Name your repository using your application name followed by your team members' last names (e.g., `AppName-LastName1-LastName2`). Ensure the repository visibility is strictly set to **Private** to prevent cross-team interference.
2. **Team Access:** Grant "Write" access only to your assigned GitHub Team members and the instructor.
3. **Initialize Core Files:** Ensure your repository includes a `.gitignore` configured for Flutter/Dart and a primary `README.md` documenting your project scope. Your code must be submitted with a clear, logical commit history.

## 📋 Project Management (Kanban)
Working effectively in small agile/scrum teams and adhering to software development life cycle (SDLC) standards is a primary course outcome. 

* Navigate to the **Projects** tab in your repository or the organization and set up a Kanban board.
* Standardize your workflow with these essential columns: `Backlog`, `In Progress`, `Code Review / Testing`, and `Done`.
* Break down your application features into manageable tasks using GitHub Issues. Link these issues to your project board. 
* Use standard Git commit phrasing (e.g., `Closes #12`) in your pull requests so that merging code automatically moves your task cards to "Done".

## 🚀 Final Project (Milestone 4) Requirements
Your final mobile application will be evaluated on your ability to design, build, and deploy a fully functional app. Ensure your repository is well-organized and all code is pushed accurately prior to your defense. Submissions that lack commits, history, or documentation entirely will result in a failing grade for the version control metric. The repository must contain the final compiled Release Build (APK / App Bundle) ready for deployment.
